# 端到端回归测试（e2e）

一条命令跑完整条业务链，无浏览器、无外部服务、无网络，可直接挂 CI / 回归门禁：

```bash
npm test          # 或 npm run test:e2e
# 退出码 0 = 全过；非 0 = 有用例失败（失败信息点到「哪一步 / 哪个人 / 为什么」）
```

实现方式：`scripts/run-e2e.mjs` 用已在 devDependencies 里的 esbuild 把
`e2e/index.test.ts`（连同 `src/logic`）打包成单个 ESM，再交给 Node 内置的
`node:test` 执行，不引入 vitest / jest / puppeteer 等新依赖。

## 测的是什么：一整条数据流，不是单个函数

每个金标准用例都按真实页面调用路径把数据推过整条链：

```
手工录入(MeasureView 建人路径) ┐
                              ├→ 分析拦截 analyzeDraft → 半厘米归一(precision)
表格导入(ImportView 两步式)  ─┘            ↓
              档位对齐 + 胸腰差型别判定(sizeRules，全整数运算)
                              ↓
                 人工覆写(留痕/校验) merge.runMerge
                              ↓
            分档小计 + 守恒等式 merge.buildSummary  ← 【对账基准】
                ┌─────────────┼──────────────────┐
          页面小计(SummaryView)  下单汇总表+打印稿   量体明细/特殊清单
          （Summary 直接渲染）   （exporter）       （exporter → CSV/XLSX）
                              ↓
                 守恒门禁 canExportOrderSheet
```

「三处呈现一致」在 `01`/`03`/`04` 组里是**双向逐档对账**：
页面 `summary.allRows` 里每一档都要在下单表、打印稿找到同数量；
下单表也不允许出现页面没有的档（防导出层私造桶）；
量体明细按姓名逐行回贴，生效号型再计数必须等于页面分档。

## 基准选择：以页面为基准，导出是被测对象

三处对不上时总要有一份说了算。本仓采用：

- **基准 = 页面汇总模型（`buildSummary` 产出的 `Summary`）**。
  下单汇总表（`exporter.buildOrderSheet / orderSheetToRows / orgUnitSheetToRows`）、
  打印稿（`buildOrderSheet().items`，与导出预览同一份数据）、
  量体明细（`detailRows`）全部是它的下游投影。
- **代价**：导出侧代码被约束为「只能投影、不能再算」，任何二次统计都要回到
  Summary 取数；测试因此必须模拟文件读回来验导出（本组内建了零依赖的 xlsx zip 解析）。
- **适用情形**：下单表是发给服装厂的外部单据，一旦页面与导出不一致，
  正确做法永远是改代码重导，而不是让用户去迁就文件——所以页面（计算真相）为基准、
  导出（外部承诺）为被测对象。

另一条路（以导出文件为基准、页面成被测对象）的代价与适用情形：
需要一份冻结的样例文件库做黄金文件对比，规则改版 / 文案调整都会大面积改黄金文件，
适合格式稳定性要求高于规则迭代速度、且有专人维护样例的团队；本项目规则版本化、
旧项目按旧版本解释，计算口径会长期演进，因此不采用。

## 用例分组（28 个，全在 `e2e/`）

| 文件 | 钉住的事 |
| --- | --- |
| `01-full-chain` | 金标准：手工+导入同一批人（含无效/错误/疑似重复/特殊体型）→ 三处呈现一致、逐号型/逐人钉数、幂等重传、CSV/XLSX 往返 |
| `02-precision-and-rules` | 半厘米一律整数比较（0.1+0.2、ULP 噪声）；167.5/182.5 在 `round_up` vs `nearest` **必须不同**（证伪）；朴素 `Math.round` 哨兵；型别区间闭端点；男女差异；v1.0.0/v1.1.0 版本锁定；负差/缺胸围定位到人 |
| `03-overrides` | 合法覆写只挪套数不挪人，守恒仍成立；规则口径 vs 生效口径同时可查；覆写到规则永不会产生的合法码；非法码/留痕缺失在入口拦住；旧档坏覆写剥离留痕回落规则 |
| `04-consistency-and-gate` | 唯一导出门禁 `canExportOrderSheet`（页面禁用与测试同判准）；未归并点名+行号；页面/导出/打印双向对账；单位小计；XLSX 与 CSV 逐行一致 |
| `05-cells-and-csv` | 逗号/双引号/换行/CRLF 转义往返；脏字符从导入走到明细；数字与文本不混（XLSX 数量列数值、号型/班级/工号文本保前导零）；BOM/TSV/分号分隔 |
| `06-legacy-archive` | 旧存档缺字段兼容策略：结构字段补默认值；缺量体数值不伪造、守恒拦住点名；坏覆写；未知规则版本回落；非法枚举容错 |
| `07-bulk-determinism` | 5000 人：解析+dry_run、runMerge、整链耗时；守恒；两遍结果逐人/逐行/字节级（CSV 数据段、XLSX 单元格含类型）一致 |

## 技术红线对应的用例

- **半厘米整数比较**：`02/精度-1、判定-4`——构造 `0.1+0.2`、`167.4999999999`、
  `167.5000000001` 等浮点噪声，断言只认半厘米整数。
- **边界取整能证伪**：`02/精度-2、精度-3`——同一输入两种边界规则必须产出不同号型，
  并保留一个专门暴露「实现退化成 `Math.round`」的哨兵断言。
- **覆写与守恒判准冲突**：`03` 全组 + `04/门禁-1`。
- **旧存档缺字段**：`06` 全组，兼容代码在 `src/logic/migrate.ts`，
  入口与 `store.initStore` 相同。
- **逗号/引号/换行单元格、数字文本混排**：`05` 全组。
- **大批量确定性与耗时**：`07`，规格书预算 5000 人归并 < 200ms、导入解析 < 2s，
  实际耗时由用例打印（本机约 10ms / 80ms 量级）。

## 失败时怎么读

每条断言的失败文案都带定位坐标，例如：

- `分档小计：170/88A 男应=3（手录甲+导入丁×2），若失败说明归并/去重某步对不上`
- `差异明细：必须点名「归不上」` / `差异原因指向型别判定步骤`
- `页面→导出：页面档 170/88A/male 在 CSV 下单表缺失`
- `XLSX：数量「12」必须是数值单元格`

node:test 会打印 TAP 风格的用例名、错误消息与堆栈，末尾汇总 `# pass / # fail`，
进程退出码非 0，门禁直接用即可。
